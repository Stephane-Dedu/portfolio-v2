## Context

Fissure is a mobile app to track calories and workouts in one place, with Gemini to make the data easier to log (React Native and Expo for the app, ExpressJS with a clean architecture for the back end, PostgreSQL for the data). It is while trying to deploy it that I got hooked on the Cloud, and the interesting part here is not the app itself: it is the path from a catastrophic first deployment to the current infrastructure.

The constraints were those of a personal project: a tight budget, the wish to keep control of the infrastructure rather than going fully serverless, and very little networking knowledge at the start. Scroll down, the architecture rebuilds itself step by step.

## What I took from it

Security has to be designed in from the start (private subnets, IAM roles, encryption), because it is much harder to add afterwards. Deploying by hand over SSH was a nightmare: Terraform and automatic deployments through ECR transformed my workflow and make rollbacks possible in minutes. And an always-on instance costs a lot even without traffic, which taught me to track costs from day one with Cost Explorer.

## What's left

The next version will add an S3 bucket with image resizing through Lambda, and a cache layer with ElastiCache Redis.

The code is private: the full write-up, with the mistakes of the first deployment and the cost breakdown, is [on the blog](/blog/fissure-retex).
